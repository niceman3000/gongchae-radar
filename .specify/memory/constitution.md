# 공채레이더 Constitution

## Core Principles

### I. 공식 데이터와 원문 우선
채용 공고와 변경점은 공공데이터포털 채용정보 API와 해당 API가 제공하는 공식 공고문을
기준으로 삼아야 한다. 화면에 표시하는 기관명, 공고명, 모집단위, 일정, 인원, 자격,
가점, 전형 정보는 원본 데이터에서 추적할 수 있어야 한다. 잡알리오 경쟁률처럼 API에
포함되지 않은 값은 팀원이 공식 화면에서 직접 확인한 경우에만 출처와 확인일을 기록해
사용하며, 자동 수집한 것처럼 표현해서는 안 된다.

### II. 코드 우선, AI 최소 사용
숫자 비교, 날짜 비교, 목록 비교, 자격 조건 매칭, 상태 판정처럼 규칙으로 처리할 수 있는
작업은 결정적 코드로 수행해야 한다. AI는 PDF의 비정형 표·문장 구조화, 문구 변경의 실질성
분류, 저장된 근거를 이용한 질의응답에만 사용한다. AI가 자격 가능 여부나 수치 계산을 단독으로
결정해서는 안 되며, 판단이 불충분하면 결과를 `애매` 또는 `확인 필요`로 표시해야 한다.

### III. 근거 없는 결과 금지
사용자에게 보여 주는 모든 변경점과 답변은 공고문 쪽수와 원문 인용을 포함해야 한다.
인용문이 해당 쪽의 추출 텍스트에 실제로 존재하는지 코드로 검증해야 하며, 검증되지 않은
항목은 확정 결과로 노출해서는 안 된다. 공고에 근거가 없으면 추정하지 않고 `명시 없음`으로
답한다. AI 답변에는 AI 생성 결과임을 표시한다.

### IV. 사전 계산과 고정 데이터
PDF 추출, AI 구조화, 전년도·당해 연도 비교는 배치 단계에서 미리 수행하고 검증된 리포트로
저장해야 한다. 사용자 요청 시점에는 저장된 리포트를 읽는 것을 기본으로 하며, 외부 API나
AI 모델 장애가 핵심 시연을 막아서는 안 된다. 제출 전 시연 데이터, 프롬프트, 결과 파일을
고정하고 동일 입력에서 동일 핵심 결과가 재현되는지 확인해야 한다.

### V. 개인정보·비밀·라이선스 보호
서비스는 이름, 연락처, 주민등록번호 등 개인 식별 정보를 수집하거나 외부 AI에 전송해서는
안 된다. 사용자 입력은 직렬, 지역, 보유 자격증 등 지원 조건으로 제한한다. API 키는 환경변수나
배포 플랫폼의 비밀 저장소로만 관리하고 코드, Git 이력, 영상, 발표자료에 포함해서는 안 된다.
사용 라이브러리는 제출 조건에 맞는 라이선스를 확인해야 하며, 현재 PDF 처리에는 MIT 라이선스의
`pdfplumber`를 사용하고 AGPL 의무가 있는 `PyMuPDF`는 사용하지 않는다.

## 해커톤 범위와 기술 제약

- MVP는 한국전력공사, 한국수력원자력, 한국중부발전의 확정된 전년도·당해 연도 공고 쌍을
  대상으로 한다. 자동 기관 확장과 자동 공고 매칭은 핵심 기능 완료 후의 선택 과제다.
- 핵심 사용자 흐름은 `조건 입력 -> 맞춤 공고 목록 -> 변경점 리포트 -> 근거 질문`의 네 단계다.
- 서비스는 추천 점수나 합격 가능성을 생성하지 않는다. 사용자가 선택한 조건과 공식 공고의
  일치 여부를 `지원 가능`, `지원 불가`, `애매`로 보여 주고 그 근거를 제시한다.
- 화면은 통합 리포트 계약을 읽어야 하며, 배치 처리의 중간 파일 구조에 직접 의존해서는 안 된다.
- Python 3.11 이상을 기준으로 하고 기존 수집·비교 코드를 우선 재사용한다. 마감 전에 기술
  스택을 바꾸려면 일정 영향과 기존 코드 재사용 가능성을 먼저 기록해야 한다.

## 개발 절차와 품질 게이트

1. 기능 구현 전 `spec.md`에서 사용자 시나리오, 범위, 수용 조건을 고정한다.
2. `plan.md`에서 기존 코드와 데이터 계약을 확인하고 새 파일과 변경 파일을 명시한다.
3. 모든 작업은 `tasks.md`의 완료 조건과 파일 경로를 기준으로 나눈다.
4. 통합 리포트는 스키마 검증을 통과해야 하며, 모든 확정 변경점의 인용 검증 결과가 성공해야 한다.
5. 대표 공고 쌍마다 팀원이 작성한 정답지와 결과를 비교하고, 불일치는 숨기지 않고 원인과
   조치 여부를 기록한다. 측정하지 않은 정확도나 시간 절감 수치를 만들지 않는다.
6. 제출 전 비밀값 포함 여부, 로그인 없는 접근, 고정 데이터 동작, 주요 화면 네 개, 오류 시
   대체 문구를 확인한다. 2026-11-23 17:00 이후에는 복구와 키 교체를 제외한 기능, 프롬프트,
   데이터 변경을 하지 않는다.

## Governance

이 Constitution은 공채레이더의 다른 개발 메모보다 우선한다. 변경이 필요하면 변경 이유,
영향을 받는 명세·코드·데이터, 재검증 방법을 기록하고 팀의 동의를 받아야 한다. 원칙 제거 또는
의미 변경은 MAJOR, 새 원칙이나 품질 게이트 추가는 MINOR, 의미를 바꾸지 않는 설명 보완은
PATCH로 버전을 올린다. 각 기능의 명세, 계획, 작업 목록과 코드 검토 시 본 문서 준수 여부를
확인하며, 예외가 있으면 `plan.md`의 Constitution Check에 이유와 대안을 명시해야 한다.
실행 방법과 현재 작업 상태는 `GUIDE.md`와 `README.md`를 따른다.
