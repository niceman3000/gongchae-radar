# Feature Specification: 공채레이더 MVP

**Feature Branch**: `001-recruitment-radar-mvp`

**Created**: 2026-11-17

**Status**: Draft

**Input**: User description: "공기업의 올해 공고와 전년도 동일·유사 공고를 비교해 취업준비생에게 필요한 변경점과 지원 조건을 원문 근거와 함께 보여 주고, 해당 근거 안에서 질문에 답하는 공채레이더 MVP"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 전년도 대비 핵심 변경 확인 (Priority: P1)

공기업 취업준비생은 관심 기관의 당해 연도 공고를 열어 전년도 동일·유사 공고와 비교된
모집인원, 지역별 인원, 지원자격, 자격증 가점, 전형 배점·배수, 일정의 변경점을 중요도순으로
확인한다. 각 결과에서 전년도 내용, 당해 연도 내용, 공식 공고문의 쪽수와 원문 인용을 함께
확인하여 직접 공고문 전체를 대조하지 않고도 바뀐 내용을 검증할 수 있다.

**Why this priority**: 전년도와 달라진 내용을 공식 근거와 함께 줄여 보여 주는 것이 공채레이더의
핵심 가치이며, 이 기능만으로도 독립적인 비교 서비스가 된다.

**Independent Test**: 확정된 공고 한 쌍을 선택했을 때 변경점 목록이 중요도순으로 표시되고,
각 확정 변경점의 전년도·당해 연도 값과 쪽수·원문 인용을 원본 공고에서 대조할 수 있으면 된다.

**Acceptance Scenarios**:

1. **Given** 전년도와 당해 연도 공고가 연결되어 있을 때, **When** 사용자가 해당 공고의 변경점
   리포트를 열면, **Then** 변경 항목별 이전 내용·현재 내용·영향받는 모집단위·중요도·근거가 표시된다.
2. **Given** 변경점에 유효한 근거가 있을 때, **When** 사용자가 근거를 확인하면, **Then** 공고문
   쪽수와 인용문이 제공되고 인용문을 해당 쪽에서 찾을 수 있다.
3. **Given** 공고에 특정 정보가 없거나 근거가 확인되지 않을 때, **When** 리포트가 표시되면,
   **Then** 시스템은 값을 추정하지 않고 `명시 없음` 또는 `확인 필요`로 구분한다.
4. **Given** 문구만 달라지고 지원자에게 미치는 의미가 같을 때, **When** 변경점이 분류되면,
   **Then** 실질 변경과 표현 변경을 구분하여 불필요한 변경 알림을 줄인다.

---

### User Story 2 - 내 조건에 맞는 공고와 지원 상태 확인 (Priority: P2)

취업준비생은 희망 직렬, 지역, 보유 자격증만 입력하고 대상 공고 중 자신의 조건과 관련된
공고를 확인한다. 각 공고에는 `지원 가능`, `지원 불가`, `애매` 중 하나의 상태와 그 판단에
사용된 공식 조건이 표시된다.

**Why this priority**: 사용자가 여러 모집단위 중 자신이 읽어야 할 공고와 조건만 먼저 좁히게 하여
공고 탐색 시간을 줄이지만, 비교 리포트가 먼저 존재해야 의미가 있으므로 P2로 둔다.

**Independent Test**: 대표 사용자 조건인 `전기 직렬`, `부산·울산 지역`, `전기기사 보유`를
입력했을 때 관련 공고가 표시되고, 각 상태의 근거를 공고 내용과 대조할 수 있으면 된다.

**Acceptance Scenarios**:

1. **Given** 사용자가 직렬·지역·자격증 조건을 선택했을 때, **When** 공고 찾기를 실행하면,
   **Then** 조건과 관련된 공고의 기관명·공고명·마감일·지원 상태·대표 변경점이 표시된다.
2. **Given** 필수조건을 충족하지 못한 근거가 명확할 때, **When** 결과가 표시되면,
   **Then** `지원 불가`와 불충족 조건의 원문 근거가 함께 표시된다.
3. **Given** 전공 인정 범위나 자격증 대체 여부처럼 자동으로 확정하기 어려운 조건이 있을 때,
   **When** 결과가 표시되면, **Then** `애매`로 표시하고 사용자가 확인할 항목을 제시한다.
4. **Given** 사용자가 조건을 입력할 때, **When** 입력 화면을 이용하면, **Then** 이름·연락처 등
   개인 식별 정보를 요구하지 않는다.

---

### User Story 3 - 공고 근거 안에서 추가 질문 (Priority: P3)

취업준비생은 선택한 공고와 변경점에 관해 자연어로 질문하고, 공식 공고문에서 확인되는 범위의
답변과 쪽수·원문 인용을 받는다. 공고에서 확인할 수 없는 질문에는 추측 대신 `명시 없음`이라는
답변을 받는다.

**Why this priority**: 표준 리포트로 해결되지 않는 추가 질문을 처리하지만, 핵심 비교와 조건 판정이
완성된 뒤에도 독립적으로 추가할 수 있으므로 P3로 둔다.

**Independent Test**: 공고에 답이 있는 질문과 없는 질문을 각각 입력해, 첫 질문에는 근거가 있는
답변이 나오고 두 번째 질문에는 `명시 없음`이 나오며 모든 생성 답변에 AI 표시가 있으면 된다.

**Acceptance Scenarios**:

1. **Given** 선택한 공고의 근거에 답이 있을 때, **When** 사용자가 질문하면, **Then** 답변과
   공고문 쪽수·원문 인용이 함께 표시된다.
2. **Given** 선택한 공고의 근거에 답이 없을 때, **When** 사용자가 질문하면, **Then** 시스템은
   내용을 만들어내지 않고 `공고문에 명시 없음`으로 답한다.
3. **Given** 시스템이 자연어 답변을 생성했을 때, **When** 답변이 표시되면, **Then** 사용자는
   해당 답변이 AI 생성 결과임을 알 수 있다.

### Edge Cases

- 전년도에 직접 대응하는 공고가 없거나 동일한 채용 차수를 확정할 수 없으면 비교 리포트를
  만들지 않고 `비교 대상 확인 필요`로 표시한다.
- 모집단위 명칭이 연도별로 달라졌지만 동일 모집단위로 볼 근거가 부족하면 자동으로 합치지 않는다.
- 기관이 인원·경쟁률·전형 세부값을 공시하지 않았으면 0으로 처리하지 않고 `기관 미공시`로 표시한다.
- 원문 인용이 제시된 쪽에서 확인되지 않으면 해당 항목을 확정 변경점으로 노출하지 않는다.
- 같은 내용이 여러 쪽에 반복되면 가장 직접적인 근거를 우선하고 필요한 경우 복수 근거를 표시한다.
- 사용 조건과 일치하는 공고가 없으면 빈 목록 대신 조건을 바꿔 보라는 안내와 현재 적용 조건을 표시한다.
- 공식 공고가 수정되거나 파일이 교체된 경우에는 현재 리포트의 기준 공고와 확인 시점을 표시한다.
- 외부 데이터나 답변 기능을 일시적으로 사용할 수 없어도 확정된 핵심 비교 리포트는 열람할 수 있어야 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 당해 연도 공고와 비교 가능한 전년도 동일·유사 공고를 한 쌍으로 관리해야 한다.
- **FR-002**: 시스템은 공고 쌍마다 기관·공고명·공고 식별값·채용기간·원문 출처를 표시해야 한다.
- **FR-003**: 시스템은 모집인원, 지역별 인원, 필수자격, 자격증 가점, 전형 배점·배수, 일정의
  전년도·당해 연도 차이를 항목별로 제공해야 한다.
- **FR-004**: 시스템은 변경점을 지원자 영향도에 따라 정렬하고 실질 변경과 표현 변경을 구분해야 한다.
- **FR-005**: 모든 확정 변경점은 공고문 쪽수와 원문 인용을 포함해야 한다.
- **FR-006**: 제시된 쪽에서 원문 인용을 확인할 수 없는 항목은 확정 결과에서 제외하거나
  `확인 필요`로 표시해야 한다.
- **FR-007**: 공고에 없는 값은 생성하거나 0으로 대체하지 않고 `명시 없음` 또는 `기관 미공시`로 표시해야 한다.
- **FR-008**: 사용자는 희망 직렬, 희망 지역, 보유 자격증을 선택할 수 있어야 한다.
- **FR-009**: 시스템은 사용자 조건과 공고 조건을 비교해 `지원 가능`, `지원 불가`, `애매` 중
  하나를 표시하고 판단 근거를 제공해야 한다.
- **FR-010**: 시스템은 합격 가능성, 개인 순위, 추천 점수를 생성해서는 안 된다.
- **FR-011**: 사용자는 목록에서 공고를 선택해 상세 변경점과 모집단위별 인원을 확인할 수 있어야 한다.
- **FR-012**: 사용자는 선택한 공고에 대해 추가 질문을 할 수 있어야 하며, 답변은 해당 공고의
  확인된 근거 범위로 제한되어야 한다.
- **FR-013**: 답변 근거가 없으면 시스템은 `공고문에 명시 없음`으로 답해야 한다.
- **FR-014**: 자연어 생성 답변에는 AI가 생성한 결과라는 표시가 있어야 한다.
- **FR-015**: 시스템은 이름, 연락처, 주민등록번호 등 개인 식별 정보를 입력받지 않아야 한다.
- **FR-016**: 핵심 시연 대상인 한국전력공사, 한국수력원자력, 한국중부발전의 확정 공고 쌍을
  로그인 없이 열람할 수 있어야 한다.
- **FR-017**: 경쟁률은 기관이 공식적으로 공개하고 팀이 출처와 확인 시점을 기록한 경우에만 표시해야 한다.
- **FR-018**: 각 리포트는 기준이 된 공고와 데이터 확인 시점을 사용자가 확인할 수 있게 해야 한다.

### Key Entities *(include if feature involves data)*

- **공고**: 한 기관이 특정 시점에 발표한 채용 공고. 기관, 공고 식별값, 제목, 채용기간,
  모집단위, 원문 출처와 확인 시점을 가진다.
- **공고 쌍**: 비교 대상으로 확정된 전년도 공고와 당해 연도 공고의 연결. 동일 기관·채용 유형·
  시기의 대응 근거와 매칭 상태를 가진다.
- **모집단위**: 직렬·지역·고용형태 등 지원자가 실제로 지원하는 단위. 인원, 자격, 가점,
  전형단계와 연결된다.
- **변경점**: 전년도와 당해 연도 사이에 달라진 항목. 이전 내용, 현재 내용, 중요도,
  실질·표현 변경 구분, 영향받는 모집단위를 가진다.
- **근거**: 결과를 뒷받침하는 공식 공고문의 쪽수와 원문 인용. 확인 상태와 출처 공고에 연결된다.
- **사용자 조건**: 사용자가 선택한 희망 직렬, 지역, 보유 자격증. 개인 식별 정보는 포함하지 않는다.
- **지원 상태**: 사용자 조건과 모집단위 조건을 비교한 `지원 가능`, `지원 불가`, `애매` 결과와 판단 근거.
- **근거 답변**: 사용자의 질문, 확인된 답변, 근거, AI 생성 표시 또는 `명시 없음` 상태.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 핵심 시연 범위에서 3개 기관의 전년도·당해 연도 공고 3쌍, 총 6개 공고를 조회할 수 있다.
- **SC-002**: 화면에 확정적으로 표시되는 변경점의 100%가 출처 공고, 쪽수, 원문 인용을 포함하고
  해당 쪽에서 인용문을 확인할 수 있다.
- **SC-003**: 대표 사용자는 직렬·지역·자격증 입력부터 관련 공고 선택과 변경점 근거 확인까지
  2분 안에 완료할 수 있다.
- **SC-004**: 팀의 원문 검토에서 근거가 없는 확정 사실은 0건이어야 하며, 근거가 부족한 값은
  모두 `명시 없음`, `기관 미공시`, `확인 필요`, `애매` 중 하나로 표시된다.
- **SC-005**: 핵심 시연 공고 3쌍 각각에서 인원·지역·필수자격·가점·전형 방식의 다섯 검토 영역이
  `확인`, `명시 없음`, `확인 필요` 중 하나로 빠짐없이 기록된다.
- **SC-006**: 공고 근거에 답이 없는 사전 질문 사례의 100%가 추정 답변 대신
  `공고문에 명시 없음`으로 처리된다.
- **SC-007**: 외부 데이터나 자연어 답변 기능이 일시적으로 중단된 상태에서도 핵심 공고 3쌍의
  목록과 변경점 리포트를 로그인 없이 열람할 수 있다.
- **SC-008**: 사용자 흐름 전체에서 개인 식별 정보 입력 항목은 0개다.

## Assumptions

- 1차 사용자는 공기업 정규직 채용을 준비하며 여러 해의 긴 공고문을 직접 비교하기 어려운 취업준비생이다.
- MVP의 핵심 비교 대상은 한국전력공사, 한국수력원자력, 한국중부발전의 사전에 확정된 공고 3쌍이다.
- 전년도 비교 공고는 기관명만 같은 공고가 아니라 채용 유형과 시기가 대응한다고 팀이 확인한 공고다.
- 사용자는 별도 계정 없이 서비스를 이용하며 입력 조건은 한 세션의 결과를 만드는 데만 사용한다.
- 지원 상태는 공고에 명시된 조건의 일치 여부이며 법적·채용상 자격을 최종 보증하지 않는다.
- 경쟁률은 핵심 판정 값이 아니며 공식 공개와 수동 확인이 완료된 경우에만 보조 정보로 사용한다.
- 자동으로 새로운 기관과 전년도 공고를 탐색하는 기능, 합격 가능성 예측, 공고 알림 발송,
  사용자 계정·이력 저장은 MVP 범위에서 제외한다.
