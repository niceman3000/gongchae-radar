# 공채레이더 전처리 규칙 모음

**마지막 갱신**: 2026-11-21 (Claude)

AI를 쓰지 않고 코드로 처리하는 규칙을 단계별로 모은 문서다.
각 규칙에는 **무엇을 하는지 / 왜 생겼는지(실제로 나온 사례) / 어느 파일에 있는지**를 적는다.

> **규칙을 바꾸면 이 문서도 같이 고친다.** (Claude·Codex 공통)
> 규칙을 바꿨을 때 정확도가 어떻게 변했는지는 `evaluation/정확도_개선_기록.md`에 기록한다.
> 새 규칙을 넣을 때는 실제로 나온 공고와 이유를 같이 적는다. 이유가 없는 규칙은 나중에 아무도 못 고친다.

전체 흐름:

```
① 공고 고르기  →  ② 작년·올해 짝짓기  →  ③ 공고문 PDF 받기  →  ④ PDF 글자 읽기
   (collect_institutions.py)                 (redownload_pdfs.py)    (build_bundle.py)
→  ⑤ 작년·올해 비교  →  ⑥ 같은 변경 묶기  →  ⑦ 한눈에 보기·카드 제목
   (diff_stage1.py)      (change_groups.py)     (notice_info.py, notice_text.py)
→  ⑧ 직렬·지원 조건 정리  →  ⑨ 사용자 조건 판정  →  ⑩ 근거 인용 확인
   (report_builder.py)       (eligibility.py, certificates.py)  (evidence.py)

③에서 PDF가 아닌 공고(그림·스캔·한글) → ⑫ 글자로 옮기기 (ocr_notices.py) → ④ 대신 쓰는 묶음
```

## ② 작년·올해 공고 짝짓기

파일: `tools/collect_institutions.py` → `pick_pair()`

**올해 공고**
- 가장 최근 공고일로부터 365일 안의 공고 중
- 그 안에서 가장 큰 채용인원의 **절반 이상**인 공고만 보고
- 그중 접수 시작일이 가장 늦은 공고
- 왜: "가장 최근 공고"만 고르면 자주 올라오는 소규모 채용이 잡힘(11-19 1차). "가장 큰 공고"만 고르면 강원랜드처럼 오래된 큰 공고가 잡힘(11-19 5차) → 큰 공채 중 최신
- **손으로 고정** (`PIN_CURR`, 11-21 팀원 점검 1번): 하반기 공고 인원이 상반기의 절반이 안 돼 빠진 곳은 올해 공고번호를 고정한다.
  사용자·평가자는 '가장 최근 공고'를 기대하기 때문 (11월에 '2026 상반기'가 뜨면 데이터가 낡아 보임)

  | 기관 | 자동 규칙이 고른 공고 | 고정한 공고 |
  |---|---|---|
  | 한국철도공사 | 297210 (26 상반기, 1,800명) | 303642 (26 하반기, 600명) |
  | 한국수자원공사 | 300029 (26 상반기 2차, 240명) | 305290 (26 하반기, 66명) |
  | 한국남동발전 | 295867 (26년 1월, 130명) | 303429 (26 하반기, 30명) |

  - 한국중부발전(302314 제2차 → 304972 제3차)은 고정하지 않음: 핵심 3곳 정답지·질문 평가표를 만든 공고라 바꾸면 96% 채점과 질문 채점이 무너짐 → 소개서 '남은 한계'
  - 고정 공고가 목록에 없으면 자동 규칙으로 고르고 그렇게 했다고 출력

**작년 공고** — 아래 순서로 찾아서 처음 후보가 나오는 단계에서 고른다
1. 올해 공고 접수 시작일보다 **300~430일** 앞(`PREV_WINDOW`) + 인원이 올해의 **30% 이상**(`MIN_SIZE_RATIO`)
2. **270~560일** 앞(`WIDE_WINDOW`) + 인원 30% 이상
3. 300~430일 앞, 인원 상관없이
4. 270~560일 앞, 인원 상관없이

- 후보 점수 = 2 × 제목 비슷한 정도 + 인원 비슷한 정도. 같으면 365일에 가까운 것
- 제목 비교 전 숫자·"년도"·"제○차"를 지움(`normalize_title`). 상·하반기, 대졸·고졸 같은 말은 남김
- 270일부터인 이유: 같은 해 상반기·하반기 공고끼리 짝짓지 않게
- 인원 조건을 넣은 이유: 서부발전 작년 공고로 소규모 공고가 잡힘(11-19 5차)

**목록 받기**
- 기관별 최근 약 2년(`RECENT_DAYS=800`), 최대 30쪽 × 100건
- 받은 목록 원본은 `data/api/list_<기관코드>.json`. `--reuse-lists`면 API 대신 이 파일을 씀(목록이 2년 전까지 닿았거나 잘리지 않았을 때만)
- 왜: LH·한전KPS·도로공사는 기간제 공고가 수백 건이라 1,000건으로는 작년 공채까지 못 닿았음(11-19 4차)

## ③ 공고문 PDF 받기

파일: `tools/collect_institutions.py` → `attachment_urls()`, `download_attachment()` / `tools/redownload_pdfs.py`

| 규칙 | 왜 (사례) |
|---|---|
| 공고문 = 첨부 중 `atchFileType == "A"`인 첫 파일 | API 규격 |
| 다운로드 주소: API가 준 `opendata.alio.go.kr/recruit/downloadAtchFile?recrutAtchFileNo=N` 대신 **`https://www.alio.go.kr/download/download.json?fileNo=N`** 을 먼저 시도, 안 되면 옛 주소 | 11-19: 옛 주소가 사이트 첫 화면(8,333바이트 웹페이지)으로 넘어감. 잡알리오 공고 페이지(job.alio.go.kr/recruitview.do?idx=공고번호)의 첨부 링크에서 새 주소 확인 |
| 받은 내용 앞 5바이트가 `%PDF-`일 때만 PDF로 저장. 아니면 저장하지 않고 "PDF 다운로드 실패"로 기록 | 11-19: 가짜 PDF 54개가 저장돼 리포트에서 "No /Root object" 오류 |
| 이미 진짜 PDF가 있으면 다시 받지 않음. 가짜 파일은 지움 | 시간·트래픽 절약 |
| PNG·JPG·HWP 공고문은 여기서 받지 않고 "PDF 원문 기능 제외"로 기록 → ⑫에서 따로 글자로 옮김 | pdfplumber로 글자를 읽을 수 없음 |
| ZIP 공고문은 받아서 안의 PDF 중 하나를 꺼냄 (아래 점수). ZIP은 매번 다시 꺼냄 | 가스공사·도로공사·수자원·전력기술·LH가 ZIP |
| ZIP 안 한글 파일 이름: 이름 표시 플래그가 없으면 cp437 → cp949로 다시 읽음 | 윈도우에서 만든 ZIP |
| ZIP 안 '붙임' PDF는 공고문 후보에서 빼고, 고른 공고문과 이름이 같은 붙임(공고문이름_붙임서류.pdf)만 뒤에 이어 붙여 한 PDF로 (쪽 번호 이어짐) | 11-20 도로공사: 필수 자격증 목록이 붙임 2에만 있음 |

**ZIP 안 공고문 고르기 점수** (`redownload_pdfs.zip_score`, 높은 것 선택, 같으면 큰 파일)
- 이름에 일반·신입·공채·대졸 중 하나 → +2
- 이름에 "일반" → +1 더
- 별정·보훈·연구직·고졸·경력·장애·계약·기간제·특수·체험형 → 하나당 −2. **단 이름에 "일반"이 있으면 감점 없음** (예: "(일반·보훈)")
- 이름에 "공고" → +1
- 공고 제목과 비슷한 정도 → +0~1
- 왜 (11-19):
  - 가스공사: 첫 방식(이름에 "공고"가 있는 첫 파일)은 연구직·별정직 공고문을 골랐음
  - 수자원: 첫 방식은 "고졸 보훈" 공고문을 골랐음
  - LH: 두 번째 방식은 "(장애인)" 공고문을 골랐음. "(일반·보훈)"도 보훈 때문에 감점돼서 점수가 같아졌기 때문 → "일반" 예외 추가

## ⑤ 작년·올해 비교 (1단계 변경 후보)

파일: `src/diff_stage1.py`

**비교 항목**
- 숫자: 채용인원
- 목록(쉼표로 나눠 빠진 것·생긴 것): 근무지역, 직무분야(NCS), 고용형태, 학력조건
  - 근무지역은 지역 별칭을 풀어서 비교 ('광주, 전남' = '전남광주' → 변경 아님, 11-21 팀원 점검 7번. 전에는 문장 줄에만 별칭을 썼음)
- 모집단위: API `steps` 이름. 비교 전 끝의 `_일반/_보훈/_장애(인)`, `(일반)/(보훈)/(장애)/(가)/(나)`를 뗌. 뗀 이름은 같은데 올해 새로 생긴 이름은 "모집단위 세분화"
- 문장(줄 단위): 전형방법, 응시자격, 결격사유, 우대사항
  - "자세한 사항은 첨부파일" 줄은 버림
  - 바뀐 줄끼리 비슷한 정도 0.55 이상이면 "바뀜", 아니면 "삭제"·"추가"

**바뀐 줄 분류** (`classify_pair`, 위에서부터 먼저 맞는 것)

| 분류 | 조건 | 처리 |
|---|---|---|
| format | 띄어쓰기·쌍점만 다름 (’‘→', ·→,) | 제외 |
| expression | 숫자가 같고, 글자·숫자 외 기호와 단독 "단,"을 빼면 같음 | 제외 (한수원 "단," 추가) |
| expression | 숫자가 같고, `SAME_MEANING` 표로 바꾸면 같음 | 제외 |
| rename | 지역 별칭을 맞추면 같음: 광주광역시, 전라남도 / 광주, 전남 / 광주전남 → 전남광주 | 표현 변경 |
| number | 숫자+단위(배수·점·명·%·개월)가 다름 | 우선 확인 |
| date | 날짜만 다름 ('24.08.07, 2025년 등) | 카드 대신 '한눈에 보기'로 |
| text | 그 밖 | 확인 필요 |

**`SAME_MEANING` 표** (원문을 보고 같은 뜻으로 판정한 것만, 11-18 사용자 지적)
- "현역의 경우," = "병역대상자는" (한수원 2025→2026 병역 문구)
- "당사 규정은" = "당사 정년은" (한수원 2025→2026 연령 문구)

**주의**: 변경 후보 id `stage1-NNN`은 순서 번호다. 규칙으로 후보가 빠지면 뒤 번호가 당겨진다 →
`evaluation/ground_truth/*_evidence.json`, `app/ui_components.py`의 `CHANGE_COPY`·`GROUP_COPY` 키를 같이 확인.

## ⑥ 같은 변경 묶기

파일: `src/change_groups.py`

- 같은 카테고리(인원·지역·자격·가점·전형·모집단위) 안에서만 묶음
- 후보마다 "바뀐 낱말": 문구 변경은 한쪽에만 있는 낱말, 추가·삭제·목록은 줄 전체 낱말
- 낱말 끝 조사(에서·으로·에게·부터·까지·에·의·을·를·은·는·로·과·와·도·만) 뗌. "이·가"는 안 뗌("평가"가 잘려서)
- 2글자 미만과 어디에나 나오는 말(경우·적용·전형·채용·신입·경력·일반 등, `STOPWORDS`)은 뺌
- **3글자 이상 핵심어 1개 이상** 공유 또는 **2글자 핵심어 2개 이상** 공유 → 같은 묶음
- 날짜만 바뀐 후보(date)는 묶지 않음
- 왜: 한수원 "자기소개서 제출 시점 변경" 하나가 후보 3개로 쪼개져 나옴(11-18)

- 제출·입력할 것: 제출/반드시 입력/입력하여야/증빙이 들어간 줄
- 우대사항: 작년과 비교해 새로 생김 / 바뀜 / 같음 표시
- 나열 나누기: 괄호 밖 쉼표로 나눔. 3개 이상 나열이면 목록으로 봄

## ⑧ 직렬·지원 조건 정리

파일: `src/report_builder.py`

- 모집단위 이름 → 직렬 (`unit_tracks()`, 11-21 팀원 점검 2번에서 고침)
  1. 이름에서 '발전'을 먼저 지움 ('대졸일반-발전기계'의 '발전기'에 든 '전기' 때문에 기계가 전기로 잡혔음)
  2. 두 직렬에 걸치는 이름 (`MULTI_TRACKS`): 이 직렬들로 찾으면 모두 나옴

     | 이름 | 직렬 |
     |---|---|
     | 전기통신 (코레일) | 전기 · ICT |
     | 차량 (코레일, '차량기계'·'차량전기'·'차량관리'는 제외) | 기계 · 전기 |
     | 전자 (낱말 맨 앞일 때만, '유전자'·'전기전자'·'전자통신'·'전자게임' 제외) | 전기 · ICT |

  3. 아니면 아래 표에서 위부터 먼저 맞는 하나 (`TRACK_PATTERNS`)

     | 직렬 | 모집단위 이름에 들어가는 말 |
     |---|---|
     | 전기 | 전기·배전·송변전 |
     | 기계 | 기계 |
     | 사무 | 사무·행정·경영·회계·법무 |
     | ICT | ICT·통신·전산·IT·정보·**시스템·인공지능·AX** (11-21 추가: 마사회 시스템개발·운영, 에스알 AX) |
     | 토목 | 토목 |
     | 건축 | 건축 |
     | 원자력 | 원자력 |
     | 화학 | 화학·환경·**화공** (11-21 추가: 가스공사·전력기술·조폐·지역난방) |
     | 수자원 | 수자원 |
     | 기타 | 위에 없음 |

  4. 한 공고의 일반 모집단위가 **전부 '기타'**면('5급갑 일반' 등) 직렬을 '전체'로 두고 모든 직렬 검색에 나오게, 판정은 '애매'
     ("모집단위 이름에 직렬 구분이 없어요") — 11-21 공항공사가 모든 직렬에서 '안 뽑는 공고'로 나오던 문제
- 모집단위 구분 (`unit_kind()`, 11-21 팀원 점검 3번): 이름 규칙이 AI 메모(`unit_notes`)보다 먼저

  | 이름에 든 말 | 구분 | 처리 | 왜 |
  |---|---|---|---|
  | 체험형 | excluded | 판정에서 빼고 "체험형 인턴·경력 채용 n개는 뺐어요" 안내 | 정규직 채용이 아님 (공고 단위에서는 이미 거름) |
  | 경력 ('경력단절' 제외) | excluded | 같음 | 신입 판정 대상 아님 (부동산원 경력직원 등) |
  | 장애·보훈·국가유공자·사회형평·자립준비·저소득·다문화·경력단절·동행·지역인재 | special | 판정에서 빼고 대상자 전형으로 안내 | 대상자만 지원 가능. 전에는 보훈만 빼서 장애인·이전지역인재 제한경쟁이 '지원 가능'으로 나왔음 (광해광업) |
  | 고졸 | condition | '애매' + "고졸 학력자만 지원할 수 있는 모집단위예요" | 학력을 입력받지 않으니 빼지도 확정하지도 않음 (고졸 준비생도 쓸 수 있게) |
  | 거주지 제한 | condition | '애매' + 거주 요건 확인 안내 | 코레일 전기통신(거주지 제한경쟁) |

  - '비수도권 지역인재 **할당제** 적용'은 일반 모집 안의 할당 비율이라 special 아님 (지역난방공사)
- AI가 쓴 문장에 프로그램 필드 이름이 섞이면 지움: 'unit_notes 참고' → '모집단위별 안내 참고' (`_clean_ai_text`, 11-21 가스기술공사). 지시문 규칙 9로도 막음
- API에 모집단위(`steps`)가 없으면 직무분야(NCS) 이름으로 직렬을 추정(`NCS_TRACKS`). 이름은 "<직렬> (직무분야 추정)", 판정은 늘 "애매"
- 근무지역: API `workRgnNmLst`
- 지원 가능 학과·자격증·가점 표
  - 핵심 3곳(한전·한수원·중부발전): `evaluation/ground_truth/<기관>_requirements.json`. 11-18 Claude가 대화 중 PDF를 읽고 작성, 인용 119개 코드 대조, **사람 재확인 전**
  - 22곳: `evaluation/ai_extracted/<기관코드>_requirements.json`. `tools/extract_requirements.py`(Claude API)로 작성, 인용 코드 대조 통과분만, 사람 재확인 전
  - 모집단위별 메모는 이름 일부(`pattern`)로 연결. '일반'이 든 pattern은 버림(일반 모집 전체가 '애매'가 되는 것 방지)
- 자동 27곳은 `tier=auto` + 화면 배지 "자동 비교 · 원문 미검증"

## ⑨ 사용자 조건 판정 (지원 가능 · 애매 · 지원 불가)

파일: `src/eligibility.py`, `src/certificates.py`

- 필수조건 불충족이 하나라도 있으면 **지원 불가**
- 모집단위 이름이 적힌 **필수 자격증(required)은 전공 조건보다 먼저** 본다. 그 모집단위의 필수 항목이 여러 개면 **그중 하나**만 있으면 됨
  (11-20 마사회 전기: '전기기사 소지자'만 지원 가능인데 공고 전체 '전공·학력 제한 없음'이 먼저 걸려 자격증 없어도 지원 가능으로 나옴 /
  한전KPS·LH: '기술사 필수'·'기사 필수'가 따로 적혀 있어 처음엔 둘 다 있어야 하는 걸로 잘못 봄)
- 모집단위가 없는 필수 항목(석유공사 토익 700점, 가스기술공사 운전면허 2종 같은 공고 전체 조건)은 화면에서 입력받지 않으므로
  '전공 제한 없음'보다 앞세우지 않는다 (11-19 이전 흐름 그대로)
- 필수조건을 모두 충족하고 수동 확인 조건이 없으면 **지원 가능**
- 데이터 없음·전공 인정·대체 자격처럼 확정 못 하면 **애매**. 데이터 부족을 "지원 가능"으로 처리하지 않음
- 공고에 그 직렬이 없음 → "직렬 없음"(목록 아래쪽). 직렬은 있는데 희망 지역 근무지가 없음 → "희망 지역에 근무지가 없는 공고"
- 지역 별칭: 전남광주·광주전남·광주·전남 → 광주 + 전남
- 특별전형 모집단위(`kind=special`)는 판정에서 빼고 따로 안내. 조건부 모집단위(`kind=condition`)는 "애매". 체험형·경력(`kind=excluded`)은 판정에서 빼고 안내 (⑧ 표)
- 모집단위의 직렬은 여러 개일 수 있음(`tracks`). 희망 직렬이 그 안에 있으면 그 모집단위를 판정
- '직접 확인할 것' 순서: 모집단위 판정 이유가 먼저, 근무지 배치 안내(`region_note`)는 맨 뒤
  (11-21 팀원 점검 4번: '애매' 한 줄 요약에 "관련 전공자인지 확인" 대신 배치 안내 문장이 나왔음)
- 외국어·병역 같은 공통 조건은 상태에 넣지 않고 "공통 확인 사항"으로 표시
- 합격 가능성·순위·추천 점수는 만들지 않음
- 이름·연락처·생년월일 같은 개인정보 칸은 받으면 오류
- 자격증: "종목 + 등급"으로 나눔
  - 예: 전기공사산업기사 → (전기공사, 산업기사), 소방설비기사(전기) → (소방설비(전기), 기사)
  - 등급 순서: 기능사 1 < 산업기사 2 < 기사 3 = 기능장 3 < 기술사 4
  - 가점은 같은 종목이면 상위 등급 1개만 셈 (전기기사 + 전기산업기사 → 전기기사)

## ⑪ AI로 지원 자격·가점 받아 적기 (LLM이 하는 유일한 일)

파일: `tools/extract_requirements.py` (Claude Sonnet 5.5), 결과 `evaluation/ai_extracted/<기관코드>_requirements.json`

- 대상: 자동 비교 27곳 중 올해 공고문이 글자 PDF인 곳(22곳). ground_truth에 파일이 있는 핵심 3곳은 건너뜀
- 추출 전에 PDF가 글자 묶음보다 새것이면 묶음부터 다시 만든다 (11-20 도로공사: 붙임 합친 37쪽 대신 옛 10쪽을 읽음)
- 보내는 글: 공고문 전체 글자가 8만 자 이하면 전 쪽, 넘으면 ④에서 고른 관련 쪽만 + API 모집단위 이름 목록
- 받는 형식: 핵심 3곳 조건 파일과 같음 (major·accepted·required·bonus, match = 이름 나열 또는 종목×등급)
- 코드 검사 (받은 뒤):
  - 인용문이 그 쪽 원문에 없으면 버림 → 근거가 하나도 안 남은 항목은 버림
  - kind·track이 정해진 값이 아니면 버림, applicable_units는 API 모집단위 이름에 있는 것만
  - 등급은 기능사·산업기사·기사·기능장·기술사만 (예: '1급'은 빼고, 그러면 종목×등급이 안 되므로 항목 버림)
  - 가점 단위: 이름에 '%'가 있으면 % (예: 주택도시보증공사 '필기 배점의 0.3%'), 아니면 점
  - 이름에 '일반'이 든 모집단위 메모는 버림 (서부발전 '(일반) 지역인재 비율' 메모 때문에 일반 모집 전체가 '애매'가 될 뻔함)
- 지시문 규칙 9 (11-21): name·text에 JSON 필드 이름(unit_notes 등)을 쓰지 말 것 (가스기술공사 'unit_notes 참고'가 화면에 보였음)
- 답 원본은 `raw/<기관코드>.txt`에 항상 저장. `--from-raw`로 AI 없이(무료) 다시 정리
- 답이 출력 한도에 걸려 잘리면 저장 안 함. 원본에서 다시 정리할 때는 온전한 항목만 살리고 `partial: true` 표시
  (11-19 지역난방·KPS·광해광업·LH: 가점표가 길어 잘림 → 공통 조건 칸은 빠짐)
- 같은 공고에서 이미 뽑았으면 건너뜀. 새 공고가 수집돼 pair_id가 바뀌면 다시 뽑고, 리포트는 예전 공고 추출본을 쓰지 않음
- 비용 상한 `--max-cost`(기본 $2)를 넘을 것 같으면 멈춤. 비용 계산(토큰 세기)은 무료
- 그림 공고(⑫, 묶음 `source: "ocr"`)만: 인용 문장이 원문에 있는데 쪽수만 틀렸고 그 문장이 **딱 한 쪽**에만 있으면 그 쪽으로 고친다.
  문장이 원문에 없거나 여러 쪽에 있으면 그대로 버림 (11-20 석유공사: 긴 그림을 1쪽으로 둘 때 AI가 8쪽·29쪽을 지어냄)

## ⑫ 그림·스캔·한글 공고문을 글자로 옮기기 (11-20)

파일: `tools/ocr_notices.py`, 결과 `data/ocr/<공고번호>/`(조각 그림·옮긴 글자·manifest) → `stage2/bundle_<공고번호>.json` (`source: "ocr"`)

대상 고르기
- 공고문이 PDF가 아님(PNG·JPG·HWP·PDF 없는 ZIP), 또는 글자 묶음의 쪽당 평균 글자가 100자 미만(스캔 PDF)
- 강제 대상 `FORCE`: 마사회 올해(293232) — PDF에 글자는 있지만 가점·자격 표가 그림
- 이미 옮긴 공고(`source`가 ocr·hwp)는 건너뜀

받을 첨부
- 공고문(A) + 이름에 가점·자격증·점수표·전형 방법·환산·우대·지역인재가 든 첨부
- 단 입사지원·지원서·직무기술·직무설명·자기소개·반환·결격·피해자·FAQ·증빙이 든 첨부는 뺌
  (한전KDN: 공고문은 스캔 1쪽뿐이고 '자격증 목록 및 점수표'는 별도 글자 PDF / 에스알: '자격가점 및 비율.pdf' / 강원랜드: '세부 전형 방법.png')
- 첨부 받기는 PDF·PNG·JPG·HWP·ZIP 모두 받는다 (`download_any`, 기존 `download_attachment`는 PDF·ZIP만 받아 그림을 못 받음). 받은 원본은 `raw/`에 저장해 다시 받지 않음
- ZIP: 한글 HWPX면 글자 꺼냄. 아니면 안의 PDF·그림·HWP 중 ③의 점수로 공고문 하나 + 이름에 위 낱말이나 '붙임'이 든 파일

파일 종류별
- 글자 있는 PDF 쪽(200자 이상): AI 없이 pdfplumber로 그대로 (표 포함)
- 스캔 PDF 쪽: 가로 1200px로 그림 변환 → 아래처럼 자름. **PDF 1쪽 = 묶음 1쪽** (위·아래 조각 글자를 합침)
- 강제 대상(마사회)은 쪽 넓이 10% 이상인 큰 그림이 있는 쪽만 그림으로 읽음 (34쪽 전부면 68조각 → 38조각)
- PNG·JPG: 아래처럼 자르고 **조각 하나 = 묶음 1쪽** (11-20 석유공사: 44조각을 1쪽으로 두니 AI가 쪽수를 지어냄)
- HWP(5.x, OLE): AI 없이 `BodyText/Section*`의 문단 글자(레코드 67)를 꺼냄. 표는 칸마다 줄로 나옴. 필요: `pip install olefile`
  - 한글 전용 기호가 두 글자(서로게이트)로 나뉘어 들어오면 한 글자로 합치고, 화면에 안 보이는 사용자 정의 영역 글자는 뺌 (11-20 광해광업: 저장 오류로 빈 파일)

그림 자르기
- 가로가 1200px보다 크면 1200px로 줄임 (작으면 키우지 않음)
- 세로 약 950px마다 자르되, 목표 위쪽 250px 안에서 **진한 점이 가장 적은 가로줄**(글자 없는 줄)에서 자름 → 글자가 조각 사이에서 안 잘림
  1200×950 ≈ 114만 화소 = AI가 줄이지 않고 그대로 보는 크기 안

옮겨 적기 (AI, `--run`일 때만)
- 지시: 보이는 글자를 위에서 아래로 그대로. 고치기·요약·설명 금지, 표는 `| 칸 | 칸 |` 한 줄씩, 숫자·기호 그대로, 못 읽으면 [?]
- 모델: Haiku 5.5 (강원랜드 시험에서 숫자·날짜·조항 틀린 곳 0, 글자 오타 2개 / Sonnet은 15배 비쌈). `--model`로 바꿀 수 있음
- 조각마다 `.txt`로 저장 → 중간에 멈춰도 이어서. 비용 한도 `--max-cost`(기본 $1.5). 출력 한도에 걸리면 끝에 `[잘림: 출력 한도]`
- `--rebundle`: AI·다운로드 없이 이미 옮긴 글자로 묶음만 다시 만듦 (쪽 나누기 규칙이 바뀌었을 때)

옮긴 글자를 쓰는 곳
- `tools/build_auto_reports._bundle_text`: 묶음 `source`가 ocr·hwp·attach면 PDF로 다시 만들지 않고 그대로 씀
- 지원 자격 추출(⑪)·질문·인용 대조 모두 이 글자를 '원문'으로 씀 → **옮기면서 생긴 오타는 인용 대조로 못 잡음**
