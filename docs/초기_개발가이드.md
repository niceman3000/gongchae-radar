## 1. 우리가 만드는 것 (1분)

공기업 채용공고는 해마다 조건이 바뀌는데, 지원자는 작년 공고와 올해 공고를 직접 열어 비교해야 합니다.
**공채레이더**는 이 비교를 자동으로 해 줍니다.

실제 결과 예시 (한국전력공사 4직급 대졸 하반기, 2025 → 2026):

| 무엇이 | 작년 | 올해 | 근거 |
|---|---|---|---|
| 서류 통과 인원 (모집인원 대비) | 15배 | 전기 분야 10배 | 공고문 5쪽 |
| 면접 배점 (직무 : 경험) | 60 : 40 | 50 : 50 | 공고문 5쪽 |
| 배전 모집인원 (일반전형 합계) | 101명 | 172명 | 공고문 2쪽 표 |
| 송변전 모집인원 | 157명 | 105명 | 공고문 2쪽 표 |

사용자는 "전기직 · 부산 · 전기기사 보유" 같은 조건만 고르면, 해당 공고들의 **변경점 리포트**를 쪽수 근거와 함께 봅니다.

## 2. 업무 흐름이 기술로 어떻게 돌아가나 (5분)

시스템은 **두 시간대**로 나뉩니다.

- **A. 뒤에서 미리 (사용자 없음, 공고가 뜰 때마다 1회)**: 공고를 모으고, 작년과 비교하고, 리포트를 만들어 저장
- **B. 사용자가 쓸 때 (실시간)**: 저장된 리포트를 조건에 맞게 보여 주고, 질문에 답함

비싼 일(PDF 읽기, AI 호출)은 전부 A에서 끝내고, B는 저장된 결과를 읽기만 합니다. 그래서 화면이 빠르고, 심사 기간에 API가 막혀도 서비스가 멈추지 않습니다.

### A. 뒤에서 미리 하는 일 (배치 처리)

| 단계 | 업무로 말하면 | 쓰는 데이터 | 파이썬이 하는 일 (파일) | AI | 만들어지는 것 |
|---|---|---|---|---|---|
| A1 공고 찾기 | 새로 뜬 공기업 신입 공채를 찾는다 | API **목록** (기관코드, 공고명, 공고기간, 채용구분) | API 호출 → 공기업 30곳·신입·정규직만 거르기 (**아직 없음**, 시연은 공고번호 직접 지정) | - | 공고번호 목록 |
| A2 작년 짝 찾기 | 같은 기관의 작년 같은 시즌 공고를 찾는다 | API 목록 (기관명, 등록일, 제목의 "하반기/제3차") | 기관·시즌 규칙으로 매칭 (**아직 없음**, 시연 3쌍은 수동 지정) | - | (작년, 올해) 공고번호 쌍 |
| A3 공고 받기 | 공고 내용과 공고문 PDF를 받는다 | API **상세** (텍스트 칸, 첨부 URL, 전형단계) | `tools/fetch_notice.py`: 상세 JSON 저장, 첨부유형 A(공고문) PDF 다운로드 | - | `api_detail_<번호>.json`, `<번호>.pdf` |
| A4 1차 비교 | 작년·올해 공고 요약을 줄 단위로 비교 | 상세 JSON의 인원·전형방법·자격·우대 칸 | `src/diff_stage1.py`: 줄 나누기 → 표기 정리 → 비슷한 줄 짝짓기 → 숫자/날짜/명칭 규칙으로 분류 | - | `stage1_result.json` |
| A5 PDF 정리 | PDF에서 볼 쪽만 뽑는다 | 공고문 PDF | `src/build_bundle.py`: 쪽별 글자+표 추출, 본문+핵심 붙임만 선택 | - | `bundle_<번호>.json` |
| A6 PDF 읽기 | 표 속 인원·가점·배점을 정리한다 | bundle | `stage2/stage2.py`: 질문문 만들기 → Claude 호출 → JSON 해석 → **인용이 원문에 있는지 검사** | Sonnet | `extract_<번호>.json` |
| A7 문장 판단 | 바뀐 문장이 실제 변경인지 가린다 | stage1의 "문구 변경" 줄 | `stage2.py`: 바뀐 두 줄만 묶어 전송 | Haiku | `text_class.json` |
| A8 리포트 | 중요한 순서로 한 장 리포트를 만든다 | stage1 + extract + text_class | 합치기, 중요도 정렬, 모집단위 인원 작년↔올해 계산 (**아직 없음**, T2) | - | `report_<쌍>.json` |

### B. 사용자가 쓸 때 (실시간)

| 단계 | 사용자가 하는 일 | 쓰는 데이터 | 파이썬이 하는 일 | AI |
|---|---|---|---|---|
| B1 조건 입력 | 직렬·지역·자격증 선택 | 사용자 입력 (**개인정보 없음**) | 입력을 필터 조건으로 변환 | - |
| B2 맞춤 목록 | 공고 목록 확인 | report들의 직렬·자격요건·모집단위 | 규칙으로 지원 가능/불가/**애매**(기본값) 판정 | - |
| B3 리포트 보기 | 공고 하나 선택 | `report_<쌍>.json` | 중요도 순 표시, "공고문 ○쪽" 표시 | - |
| B4 질문 | "전기기사 가점은 몇 점?" | report + 인용 문장 | 관련 항목만 골라 질문과 함께 전송, 답변에 근거 쪽 표시 | Haiku 또는 Sonnet |

## 3. 우리가 쓰는 데이터 (3분)

| 데이터 | 어디서 받나 | 무엇이 들어 있나 | 어디에 쓰나 | 주의 |
|---|---|---|---|---|
| ① API 목록 | data.go.kr `recruitment/list` | 공고번호, 기관명·기관코드, 제목, 공고기간, 고용형태, 채용구분, 지역, 직무분야 | A1 공고 찾기, A2 짝 찾기 | 첨부·전형단계는 비어서 옴 |
| ② API 상세 | data.go.kr `recruitment/detail?sn=` | ①+ 채용인원, 응시자격, 결격사유, **전형방법**, 우대사항, `files[]`(PDF 주소), `steps[]`(모집단위별 응시·선발) | A3, A4 1차 비교, 경쟁률 | `steps` 숫자는 기관에 따라 비어 있음 |
| ③ 공고문 PDF | ②의 `files[]` 중 유형 A | **모집단위·지역별 인원표, 자격증 가점표**, 전형별 배점·배수, 사전 예고, 일정 | A5~A6 AI 추출 | 일부 HWP, 표가 깨지는 PDF 있음 |
| ④ 잡알리오 경쟁률 화면 | job.alio.go.kr 공고 상세 | 전형 단계별 응시·선발 인원 | API에 없을 때 시연 수치 인용 (출처 표기) | **크롤링 금지**, 사람이 확인한 값만 |
| ⑤ 사용자 입력 | 화면 | 직렬, 지역, 보유 자격증 | B1~B2 판정 | 이름·연락처는 받지 않음 |

**핵심**: ②(API 상세)의 텍스트만으로 큰 변경은 대부분 잡히고, ③(PDF)은 ②에 없는 **표 속 숫자**를 위해 씁니다.

### 데이터가 실제로 바뀌어 가는 예시 (한전, 실제 출력)
```
[② API 상세 · 2025] scrnprcdrMthdExpln
  "○ 외국어성적(100점), 자격증가점(사무20, 기술40), / 사무 : 50배수, 기술 : 15배수"
[② API 상세 · 2026]
  "○ ... / 사무 : 50배수, 전기(배전, 송변전) : 10배수, 기술(전기 외) : 15배수"
        │  diff_stage1.py : 숫자+단위('배수')가 다름 → number
        ▼
[stage1_result.json]
  {"field":"전형방법","type":"number",
   "prev_numbers":["100점","50배수","15배수"],
   "curr_numbers":["100점","20점","40점","50배수","10배수","15배수"]}
        │  리포트 합치기(T2) : importance 1, 근거 쪽은 2단계 extract의 evidence(5쪽)
        ▼
[report_한전.json]
  {"title":"서류 통과 인원 15배 → 10배 (전기)",
   "evidence":{"page":5,"quote":"...","verified":"쪽 일치"}}
        │  화면(B3)
        ▼
  "서류 통과 인원이 모집인원의 15배 → 10배로 줄었어요 · 공고문 5쪽"
```

## 4. 파이썬의 역할 한눈에 (1분)

Claude가 **두뇌**라면, 파이썬은 **손발과 감시자**입니다. AI가 하는 일도 파이썬이 시키고, 결과를 파이썬이 검사합니다.

| 역할 | 하는 일 | 쓰는 도구 | 파일 |
|---|---|---|---|
| 가져오기 | 공식 API 호출, PDF 다운로드 | `urllib` (표준) | `tools/fetch_notice.py` |
| PDF 다루기 | 쪽별 글자·표 추출, 볼 쪽 고르기 | `pdfplumber` | `src/build_bundle.py` |
| 비교·규칙 | 줄 짝짓기, 숫자·날짜·명칭 판별, 모집단위 이름 맞추기 | `difflib`, `re` | `src/diff_stage1.py` |
| AI 시키기 | 질문문 만들기, Claude API 호출, 결과 JSON 해석 | `urllib` (HTTP POST) | `stage2/stage2.py` |
| 검사하기 | AI가 쓴 인용 문장이 원문 그 쪽에 실제로 있는지 대조 | 문자열 비교 | `stage2.py`의 `verify()` |
| 저장하기 | 모든 단계 결과를 JSON으로 저장 (다음 단계의 입력) | `json` | 전부 |
| 판정·화면 | 조건별 가능/불가/애매 판정, 화면 표시 | Streamlit 등 (**예정**) | T3 |

## 5. 왜 이렇게 설계했나 (2분, 심사·발표 때 설명해야 하는 부분)

| 결정 | 이유 |
|---|---|
| 크롤링이 아니라 **공식 API** | 대회 규칙상 무단 수집은 심사 제외 사유. 공식 API는 2018년 이후 11만여 건을 주고, 공고문 PDF 주소까지 준다 |
| **코드로 먼저 비교**, AI는 나중 | API 텍스트만으로도 핵심 변경(배수·배점·인원)이 잡힌다. AI 비용·오류를 줄이고, "AI 없이도 되는 건 AI를 안 썼다"가 설계 근거가 된다 |
| AI에는 **필요한 쪽만** 보냄 | 한전 공고 24쪽 중 10쪽(본문 + 핵심 붙임)만 전송 → 토큰 약 1/3 |
| 모든 값에 **쪽수 + 원문 인용**, 코드로 검증 | AI가 지어낸 값을 걸러내기 위해. 심사 항목 "AI 오류 대응"의 핵심 근거 |
| 변경점 리포트는 **미리 계산해 저장** | 심사 기간(~11/30, 본선 ~12/7) 동안 API 한도·장애와 무관하게 화면이 떠야 함 |

## 6. 준비물 (10분)

### 6-1. Python

- Python 3.11 이상. 설치할 때 "Add python.exe to PATH" 체크.
- 확인: `python --version`
- 1·2단계 실행은 **표준 라이브러리만** 사용. PDF 처리(build_bundle.py)만 `pip install -r requirements.txt` (pdfplumber).

### 6-2. 키 두 개 (각자 발급, 절대 공유 금지)

| 키 | 어디서 | 쓰는 곳 | 환경변수 이름 |
|---|---|---|---|
| 공공데이터포털 인증키 | data.go.kr → "재정경제부 공공기관 채용정보 조회서비스" (오픈API) → 활용신청 → 마이페이지 → **일반 인증키(Decoding)** | 공고 수집 | `JOB_API_KEY` |
| Claude API 키 | console.anthropic.com → 결제 수단 등록 → API Keys | 2단계 AI, 질문 답변 | `ANTHROPIC_API_KEY` |

- 공공데이터포털 활용신청은 보통 바로 승인됩니다. 승인 직후 "등록되지 않은 인증키" 오류가 나면 30분~1시간 뒤 다시 시도하세요.
- Claude 콘솔에서 **월 사용 한도(spend limit)** 를 낮게 걸어 두세요. 대회 규칙이 "심사 기간 동안 사용량 한도·과금 설정 점검"을 요구합니다.

### 6-3. 환경변수 넣기 (Windows PowerShell)
```powershell
# 지금 열린 창에서만 유효
$env:JOB_API_KEY = "..."
$env:ANTHROPIC_API_KEY = "..."

# 영구 저장 (새 창부터 적용)
setx JOB_API_KEY "..."
setx ANTHROPIC_API_KEY "..."
```

### 6-4. 절대 하지 말 것

- 키를 코드, 깃, 카톡, 캡처, 발표자료에 넣기 (대회 규칙 위반)
- 실제 개인정보(이름·연락처)를 AI에 보내기. 사용자 입력은 직렬·지역·자격증 같은 **조건만** 받습니다.
- PyMuPDF 사용 (AGPL 라이선스). pdfplumber(MIT)를 씁니다.

## 12. 용어

- **공고번호(sn)**: API의 `recrutPblntSn` = 잡알리오 공고 주소의 idx. 모든 파일 이름의 기준
- **모집단위**: 공고 안의 지원 단위 (예: 배전(일반), 송변전(보훈)). 해마다 이름이 조금씩 바뀌어 `unit_base()`로 맞춤
- **배수**: 다음 단계로 통과시키는 인원 = 모집인원 × 배수 (서류 10배수 = 모집인원의 10배까지 통과)
- **이전지역인재**: 본사가 옮겨 간 지역(한전은 광주·전남) 학교 출신 대상 모집
- **1단계 / 2단계**: 1단계 = API 텍스트를 코드로 비교, 2단계 = PDF를 AI로 읽기
